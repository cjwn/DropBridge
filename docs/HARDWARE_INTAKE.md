# 硬件接入与驱动绑定检查单

状态：**等待目标网卡接入**。本页只定义操作和证据要求，不代表已经做过驱动绑定。

## 1. 只读枚举（不需要授权，不改任何东西）

1. 把 RTL8821CU 网卡直连主板 USB 口（先不要经过 hub），记录插入的本地时间。
2. 运行：

   ```powershell
   .\tools\Inspect-Hardware.ps1
   ```

3. 脚本把完整枚举写入 `evidence/usb-devices.local.json`（含设备实例路径，已被 `.gitignore` 排除，不提交），并在控制台打印。

要记录的信息：

- VID/PID；已知目标 `0bda:c811`、`0bda:c820`，ZeroCD 形态可能是 `0bda:1a2b`；
- 设备类别与接口数量（复合设备）；
- 当前驱动（`usbccgp`、Realtek 厂商驱动、WinUSB 等）；
- USB 速率（High/ SuperSpeed）与端口路径（同一 VID/PID 多只时用于区分）；
- 序列号只写进本地证据，不提交。

**ZeroCD 陷阱**：如果枚举成 `0bda:1a2b` 且带 CD-ROM/存储接口，说明它先以安装盘形态出现。不要自动 eject、`usb_modeswitch` 或改注册表；先记录，再和用户确认是否允许切模式。

## 2. 身份交叉确认

VID/PID 只能证明「这是哪一款 USB 设备」，不能证明硅片就是 RTL8821CU。完整确认需要：

1. 设备管理器 → 属性 → 详细信息 → 硬件 ID；
2. 驱动 INF 与版本；
3. 芯片 ID：devourer 在初始化时读 `SYS_CFG2 0x00FC`，RTL8821C 为 `0x09`。**这一步会写芯片状态，属于 Phase 1 初始化实验，不是只读枚举**，必须先获得授权。

Phase 0 只要求完成第 1、2 项并留下记录。

## 3. 驱动绑定前必须准备好的东西

绑定 WinUSB 是 Phase 1 的事，且必须先有恢复方案：

- 原始驱动：`pnputil /enum-drivers`、设备实例的 `DEVPKEY_Device_DriverInfPath`、驱动版本；
- 目标接口：devourer 按 vendor 接口（带 bulk IN/OUT 端点）选择并 claim，不能想当然绑整个复合设备；
- 恢复步骤：设备管理器卸载设备（不删除驱动）→ 扫描硬件改动；必要时 `pnputil /add-driver <inf> /install`；
- 权限：绑定需要管理员；绑定完成后，普通权限进程能否打开设备要实测；
- 网络：绑定后该网卡不再供 Windows 普通 Wi-Fi 使用；保持有线/I226 或另一块网卡上网。

禁止事项（项目约定）：

- 不自动替换驱动、不改网络/防火墙；
- 不运行上游安装器或会发射无线帧的脚本；
- 不在没有目标接口和恢复步骤的情况下做绑定。

## 4. 需要用户明确授权的动作

| 动作 | 为什么要授权 | 风险 |
| --- | --- | --- |
| 安装/替换 WinUSB 绑定 | 改变系统设备驱动 | 网卡暂时不能当普通 Wi-Fi 用 |
| 首次 `Init` / 固件下载 | 写芯片寄存器、加载固件 | 设备可能进入异常状态，需要拔插/重新枚举 |
| 任何 TX | 会实际发射无线帧 | 频谱干扰、合规责任 |
| 切换 ZeroCD 模式 | 改变设备枚举形态 | 可能丢失安装盘接口 |
