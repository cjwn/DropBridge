## 有价值的计数差异

按各次上传起止范围内的首末 AWDL 采样取差，采样边界略短于完整上传：

- 关闭第一轮：RX data 22,377、TX data 14,128，TX/RX 约 0.631；
  joined 增量为 0，邻居数范围 1–2。
- 关闭第二轮：RX data 22,336、TX data 14,234，TX/RX 约 0.637；
  joined 增量为 0，邻居数范围 1–3。
- 历史开启成功轮：RX data 21,769、TX data 2,166，TX/RX 约 0.0995；
  joined 增量 20,570，邻居数 1。

关闭后的回程数据帧明显更多，**与 TCP ACK 开销增加的解释相容**，但
AWDL data 不是 TCP ACK 专用计数，而且包含所有可见邻居。没有解析 TCP
载荷/标志之前，不能把这些数全称为 ACK，也不能把速度差全归给它。

本端没有换台，温度读数维持 `28/+2`；实际对端序列和邻居数有变化。
这不是同一时段交替进行、完全匹配环境/初态的严格 A/B。

## 结论与后续

1. 当前没有看到关闭合并带来的提速，不据此永久删除合并或更改默认。
2. 两轮未超时是本轮实测事实，不足以排除合并或证明它是原断流根因。
3. 保留开关便于复现；后续仍应按 Q25 采集载荷、TCP seq/ACK/窗口、
   IPC 失败、pbuf/input 丢弃及数据线程健康，区分回程开销和真正丢弃。
4. 如继续比较速度，应在可记录的同一状态/时段做 on/off 对照，明确
   手机实际信道序列与其它邻居。不要同时修多个数据面问题再比较。

测试后已停止本次项目链路，无残留；MI_02 仍 WinUSB/OK，MI_00 仍为原有
Error。未额外执行设备/Hub 复位、驱动变更或网络配置修改。默认合并仍开启。
