## 能排除什么，仍不知道什么

证据支持“控制面仍活动、上传数据面停顿”，不支持把它直接定性为整个
USB/RX 进程假死。同步树计数保持 `metric 200 / counter 100000`，本段没有
主控被抢的记录。现有证据也没有显示断流窗口出现长时间换台等待。

仍不能证明：手机已停止空口发送、硬件 ACK 正常到达手机、TCP ACK 已到达
手机，或跨频段功率/天线状态正确。USB 提交计数和寄存器回读均不是这些证明。
`netd.log` 只有启动记录，缺少连接字节进度与 TCP 序列/窗口证据；目前不能
把停顿归因于 TCP 或排除 TCP。RSSI 只对实际收到的有效样本有意义，零帧
时的 `rssi=0/rssi_n=0` 不表示信号降到零。

  同时必须移除 `AWDL_FOLLOW_MASTER_SEQ`，避免继承环境改变序列。

  对端空口 ACK。因此本次不据此关闭 ACK 排查方向。

## 下一组实验

只比较信道调度：同一构建、149/20、metric 200/counter 100000、同一视频、
位置与手机设置。A 固定 149（公告与实际序列一致），B 当前 social
（slot 8 为 6，其余 149）。保留完成确认、功率/天线补偿、温度补偿与其它
参数，先不同时修改这些项，也不添加自动设备复位。

固定模式可能使发现/同步变慢；记录看到接收端的时间和手机是否实际跟随，
不能只凭参数宣称 A 已成立。每组同一文件三次，不在传输间重启或拔插，
记录成功数、真实文件字节/墙钟耗时、两端可获得的哈希及失败时刻。
跨组保留启动耗时、初始温度和主控状态；必要时再做反序复测，避免把运行
时间造成的退化误认为模式差异。任一组断流先保留日志，不追加恢复动作。

若 A/B 都断流，下一项才是采集硬件 ACK 与 TCP 回程序列/窗口；若只有 B
复现，再分别隔离跨频段功率/天线恢复与调度。三次全成功只是下一步诊断
基线，不替代最终方案的连续 20 次、24 小时和速度发布门槛。

### Q24：真机结果（未通过验收）

用户本轮确认方便配合 iPhone，已做两组尝试。两组使用同一个新监管
`0741be7`、同一原后端 `dist/app/20261028-143130`、同一证书/实例 ID 和
接收目录；只改变 fixed/social 模式，未修改无线补丁。

A 固定 149，会话 `20261028-150311`：

- 启动 15:03:11，已有固件路径出现一次 `FW ready check failed` 后重试，
  radio 15:05:11 就绪，启动约 120 秒。温度读数 `28/+2`。
- 第一次 15:07:18.833–15:08:49.969：29,456,959 文件字节 / 91.136 秒
  = **0.32322 MB/s**，完整落盘；SHA-256 与此前接收的同一视频一致，
  仍没有手机源文件哈希。
- 第二次 15:10:30.267–15:15:54.080：323.813 秒后 HTTP 408，累计
  15,982,835 传输体字节，最后 30 秒无上传内容。没有完成文件。
- 整组只驻留 149，零换台记录。手机公告仍是包含 36/149/6 的稀疏序列，
  没有观察到它采纳全 149。第二次失败后按停止条件取消第三次，未中途
  重启、拔插或改变参数。
- 接收端最后的空窗内，AWDL action RX 仍增加 53、RX data 增加 7、
  joined 不变、TX data 增加 7；radio 偶有单个数据帧，不能等同于文件
  内容还在推进。分析器现支持直接关联接收端声明的 30 秒无内容窗口。

B social，会话 `20261028-151652`：

- 启动 15:16:52，radio/receiver 15:17:35 就绪，约 43 秒；主控正常，
  记录 264 次切入 6 的换台，能看到手机邻居。
- 用户报告隔空投送列表中没有 AirBridge32，关闭并重新打开分享面板后
  仍没有。接收端零 `/Discover`、零 `/Upload`。记录为**发现失败**，
  不是上传失败，也没有 B 组吞吐数字。

结论：**仅停用当前跨频段调度不足以解决问题**；固定 149 下也复现了
长传输断流。但两组没有从物理冷启动的同一射频初态开始（启动重试也
不同），B 更未进入上传，因此不能彻底排除之前换台遗留的射频状态，
不能宣称完成了有效的三次对三次性能 A/B，更不能判断哪种模式更快。

参考 WinAWDL `awdl/win/io_win.c`，`joined` 是被 TCP 合并器追加的段数，
不是所有有效上传帧数；少量 RX data 或 joined 为零都不能代替 TCP 载荷
字节观测。下一项应在 IPC→lwIP→本地 receiver 边界记录载荷、序列、ACK
与通告窗口，区分未收到新内容、重复段、零窗口及中间层丢弃。现有日志
尚不足以判定其中哪一个成立，暂不靠自动重启掩盖问题。

两组原始日志分别备份至 `build/diagnostics/fixed-20261028/` 和
`build/diagnostics/social-20261028/`，旧会话冻结副本在
`build/diagnostics/baseline-20261028/`，避免日志轮转删除。脱敏结果见
`evidence/fixed-channel-transfer-2026-10-28.json` 与
`evidence/social-discovery-2026-10-28.json`。

实验链路已停止，进程无残留；MI_02 仍为 WinUSB / OK，MI_00 蓝牙与实验前
一样是 Error。没有额外执行设备/Hub 复位、驱动更换或网络配置修改。
