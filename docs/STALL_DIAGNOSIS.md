## 能排除什么，仍不知道什么

证据支持“控制面仍活动、上传数据面停顿”，不支持把它直接定性为整个
USB/RX 进程假死。同步树计数保持 `metric 200 / counter 100000`，本段没有
主控被抢的记录。现有证据也没有显示断流窗口出现长时间换台等待。

仍不能证明：手机已停止空口发送、硬件 ACK 正常到达手机、TCP ACK 已到达
手机，或跨频段功率/天线状态正确。USB 提交计数和寄存器回读均不是这些证明。
`netd.log` 只有启动记录，缺少连接字节进度与 TCP 序列/窗口证据；目前不能
把停顿归因于 TCP 或排除 TCP。RSSI 只对实际收到的有效样本有意义，零帧
时的 `rssi=0/rssi_n=0` 不表示信号降到零。

## 对照的源码依据

- `upstream/devourer` 固定在 `f7e073175852eeb87ccab7bfa619c41156a1b26b`。
  `docs/experiments/dwell1-ab-injection.md` 区分命令提交和真实完成，并要求
  用正确信道的独立接收见证判断空口效果。它的 DUT 是 8822BU、36↔40，
  不能直接当成本机 8821CU、149↔6 的结论；只复用实验原则，没有复制代码。
- WinAWDL 的 OWL 子库固定在 `da255a70f221784c836d943dd3f243bc798f223b`。
  `src/channel.c::awdl_chanseq_init_static` 用主信道填满序列；本项目补丁
  `patches/owl-airbridge.patch` 在 `AWDL_CHANSEQ` **存在**时把 slot 8 改为 6。
  所以 `AWDL_CHANSEQ=fixed` 或 `0` 都不能关闭社交时隙，必须移除此变量。
  同时必须移除 `AWDL_FOLLOW_MASTER_SEQ`，避免继承环境改变序列。
- OWL `daemon/core.c::awdl_send_unicast` 按双方时隙安排回程数据；radio
  `src/radio_usb/main.cpp` 的 TX 计数只表示 `send_packet` 返回成功，未报告
  对端空口 ACK。因此本次不据此关闭 ACK 排查方向。

## 下一组实验

只比较信道调度：同一构建、149/20、metric 200/counter 100000、同一视频、
位置与手机设置。A 固定 149（公告与实际序列一致），B 当前 social
（slot 8 为 6，其余 149）。保留完成确认、功率/天线补偿、温度补偿与其它
参数，先不同时修改这些项，也不添加自动设备复位。

固定模式可能使发现/同步变慢；记录看到接收端的时间和手机是否实际跟随，
不能只凭参数宣称 A 已成立。每组同一文件三次，不在传输间重启或拔插，
记录成功数、真实文件字节/墙钟耗时、两端可获得的哈希及失败时刻。
跨组保留启动耗时、初始温度和主控状态；必要时再做反序复测，避免把运行
时间造成的退化误认为模式差异。任一组断流先保留日志，不追加恢复动作。

若 A/B 都断流，下一项才是采集硬件 ACK 与 TCP 回程序列/窗口；若只有 B
复现，再分别隔离跨频段功率/天线恢复与调度。三次全成功只是下一步诊断
基线，不替代最终方案的连续 20 次、24 小时和速度发布门槛。
